# ADR-0009: Хранить тексты в YAML и отклонять невалидный контент при старте

Дата: 2026-11-06  
Статус: accepted  
Supersedes: —  
Superseded by: —  
Issue / PR: —

## Контекст

Имена, фразы и реакции меняются чаще игровых правил. Их размещение в Python затрудняет редакторскую работу, а ошибка в контенте, обнаруженная только после нажатия кнопки, ломает живой сценарий. При этом не каждая механика должна становиться произвольно расширяемой только редактированием YAML.

Решение зарегистрировано ретроспективно. Схемы и алгоритмы разнообразия R1–R3 закреплены в ADR-0001 и его спецификации.

## Решение

- Пользовательские тексты на русском выносятся в `content/*.yaml` или в модуль текстов представления, а не смешиваются с правилами сервисов.
- YAML содержит имена и фразы прилётов, действия и реакции прогона, реакции на исходы плевка, предсказания, тексты достижений, задания и варианты часовых поясов.
- Контент загружается один раз при старте. Отсутствие обязательных файлов, полей и реакций, неверные типы, дубли идентификаторов, неподдерживаемые плейсхолдеры, битые ссылки и слишком длинные callback отклоняют запуск.
- Идентификаторы опубликованного контента стабильны. Для предсказаний сохраняются выбранный ID и отрендеренный текст, чтобы редактирование YAML не переписывало уже подготовленную выдачу; подробности — в ADR-0001.
- Расширение существующих списков имён, фраз и реакций не требует изменения механики. Добавление нового задания, достижения, исхода или формата требует изменения и проверки кода: их набор и условия намеренно ограничены реализацией.
- Имена голубей пишутся в именительном падеже, чтобы не требовать склонения. Формулировки действий участников не угадывают пол по имени.
- Генерация игрового контента через LLM и автоматическая перезагрузка YAML в работающем процессе не используются.

## Последствия

### Положительные

- Редактирование большинства текстов не требует изменения бизнес-логики.
- Ошибка контента останавливает запуск до публикации или нажатия, а проверки одинаковы для всех чатов.
- Сохранённые идентификаторы и тексты делают повторную отправку и историю устойчивыми к последующим правкам.

### Отрицательные и ограничения

- Изменение контента требует перезапуска процесса и выпуска образа, в который он включён.
- YAML не является свободной системой плагинов: новые механики и их условия остаются в коде.
- Стабильные идентификаторы нельзя переиспользовать для другого опубликованного текста; объём проверок растёт вместе со схемами контента.

## Рассмотренные альтернативы

- **Хранение всех текстов в сервисах.** Отклонено: смешивает правила и редакторскую работу.
- **Проверка значения только в момент использования.** Отклонена: переносит ошибку конфигурации в пользовательский сценарий.
- **Произвольное добавление механик через YAML.** Отклонено: условия, транзакции и тесты всё равно требуют кода.
- **Горячая перезагрузка контента.** Отклонена для текущего масштаба: усложняет согласованность уже сохранённых колод и текстов.
