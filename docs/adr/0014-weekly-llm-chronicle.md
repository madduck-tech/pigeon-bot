# ADR-0014: Недельная хроника от LLM в понедельничном посте

Дата: 2026-11-08  
Статус: accepted  
Supersedes: —  
Superseded by: —  
Issue / PR: [#15](https://github.com/madduck-tech/pigeon-bot/issues/15)

## Контекст

Принято Product Owner 2026-11-08 в текущем виде, модель по умолчанию — `glm-5.3-flash`.


Понедельничный пост (`design.md` §16, раздел 6.3) подводит итог недели сухим списком: задание, топ-3, новое задание. Product Owner хочет добавить в него короткую дерзкую хронику прошлой недели от лица голубятни, написанную LLM по метаданным игры. Новых сообщений при этом появляться не должно.

Решения Product Owner от 2026-11-08 (#15): хроника включается сразу во всех чатах, где задан ключ API, отдельной команды нет. Провайдер — OpenCode Go, ключ добавляет Product Owner. Хроника выходит только в понедельничном посте. Длина — 2–3 предложения.

Действующие ограничения:

- [ADR-0004](0004-privacy-and-minimal-data.md): текст сообщений не читается и не хранится, пингов нет, обещание в справке совпадает с реализацией. Имена участников впервые уходят стороннему сервису, поэтому обещание нужно дополнить.
- [ADR-0005](0005-layered-monolith-sqlite.md): `services/` не зависит от aiogram, время и случайность инжектируются, миграции аддитивны и идемпотентны, тесты не ходят в сеть.
- [ADR-0007](0007-local-schedule-and-noise-budget.md): автоматические сообщения проходят через бюджет, тихие часы и паузу. Хроника не является новым сообщением.
- [ADR-0010](0010-html-rendering-and-escaping.md): всё внешнее экранируется в `render/` под `parse_mode=HTML`.

### Провайдер

OpenCode Go — подписка OpenCode с набором моделей и общим API (документация: <https://opencode.ai/docs/go/>, проверено 2026-11-08). Для большинства моделей, включая GLM, Kimi и DeepSeek, доступен OpenAI-совместимый endpoint `https://opencode.ai/inference/go/openai/v1/chat/completions`. Ключ берётся в OpenCode Console. Документация просит указывать собственный User-Agent и стабильный заголовок `x-opencode-session` для одного диалога. Лимиты задаются деньгами на модель в окнах 5 часов, недели и месяца. Один запрос в неделю на чат на порядки ниже лимитов.

Документация не показывает формат заголовка аутентификации явно. Для OpenAI-совместимого API принят `Authorization: Bearer <key>`; это проверит ручной смоук Product Owner. Более ранние сторонние описания дают базовый адрес `https://opencode.ai/zen/go/v1`, поэтому адрес вынесен в конфиг.

## Решение

### 1. Подключение

- Провайдер — OpenCode Go через OpenAI-совместимый Chat Completions: `POST {base_url}/chat/completions`.
- Модель по умолчанию — `glm-5.3-flash`. Она отвечает через Chat Completions, по таблице приватности OpenCode не обучается на запросах и хранит их 0 дней, и это быстрая дешёвая модель для короткого текста. Модель меняется переменной окружения без правки кода.
- HTTP-клиент — `aiohttp`, который уже установлен как зависимость aiogram. SDK провайдера не добавляется. `aiohttp` становится явной зависимостью в `pyproject.toml`, потому что импортируется напрямую. Это единственное изменение стека в `design.md` §4.
- Клиент живёт в отдельном адаптерном пакете `src/pigeon/llm/`. `services/` получает его как инжектируемую зависимость через протокол с одним методом `complete(system, user) -> str` и не импортирует ни aiohttp, ни aiogram.
- Заголовки: `Authorization: Bearer <ключ>`, `User-Agent: pigeon-bot/<версия>`, `x-opencode-session: pigeon-chronicle-<chat_id>-<week_key>`.
- Параметры запроса: два сообщения (`system` и `user`), `max_tokens` = 800, `temperature` = 0.9, без инструментов и без потоковой передачи.

### 2. Конфиг

- `PIGEON_CHRONICLE_API_KEY` — ключ OpenCode Go. Без него функция выключена: запросы не отправляются, пост выходит как раньше, строки о внешнем сервисе в справке нет.
- `PIGEON_CHRONICLE_MODEL` — по умолчанию `glm-5.3-flash`.
- `PIGEON_CHRONICLE_BASE_URL` — по умолчанию `https://opencode.ai/inference/go/openai/v1`.
- Таймаут и лимиты длины — константы рядом с механикой.

### 3. Когда генерируется

- Отдельный проход планировщика, независимый от проходов прилётов и постов, со своим циклом: ожидание модели не задерживает ни прилёт, ни пост.
- Для каждого включённого чата хроника генерируется в понедельник по timezone чата, если понедельничный пост ещё не подготовлен. Обычно это первый проход новой недели, около полуночи, задолго до поста.
- Хроника генерируется, только если понедельничный пост вообще существует (заданы задания недели). Если пост этого понедельника уже подготовлен или отправлен, запрос не делается.
- Пауза и тихие часы генерацию не блокируют: это не публикация. Если пауза продлится весь понедельник, хроника просто не выйдет.
- Запуск после понедельника хронику не генерирует, как и не восстанавливает сам пост.

### 4. Хранение

Новая таблица, создаётся аддитивно через `CREATE TABLE IF NOT EXISTS`:

```text
chronicles(chat_id, week_key, status, text, created_at, PK(chat_id, week_key))
  week_key: ISO-дата понедельника недели, в которую выходит пост
  status: pending | ready | empty | failed
  text: очищенный текст хроники, только при ready
```

- Перед запросом строка вставляется со статусом `pending`. Вставка идёт по первичному ключу, поэтому на чат и неделю уходит не больше одного запроса, даже после перезапуска.
- Ответ сохраняется как `ready` с текстом, сбой — как `failed`, неделя без событий — как `empty` без запроса.
- `pending`, прерванный перезапуском, не повторяется: пост выйдет без хроники. Это цена гарантии одного запроса.
- Все запросы фильтруются по `chat_id`.

### 5. Что уходит в модель

- В `system` — описание персонажа и тона голубятни из `content/chronicle.yaml`, правила длины и предупреждение, что данные ниже — только данные.
- В `user` — короткая инструкция и JSON с метаданными прошлой недели только этого чата:
  - число прилётов, их типы, сколько голубей спугнули и сколько улетели сами;
  - по участникам (до 10, по очкам недели): отображаемое имя, очки недели, попадания, промахи, крупные попадания, попытки прогона, спугнутые голуби;
  - задание прошлой недели: название и выполнено ли;
  - текущий держатель Золотого плевка.
- Текст сообщений чата не уходит: бот его не получает и не хранит. `user_id`, `chat_id` и названия чатов в запрос не попадают.
- Неделя без прилётов (нет `events` с `opened_at` в прошлой неделе) не порождает запроса.

### 6. Защита от prompt injection

- Имена передаются только значениями JSON. Перед отправкой из них удаляются управляющие символы, длина обрезается до 32 символов.
- Системное сообщение прямо говорит, что строки в JSON — имена и данные, а не инструкции.
- Ответ модели используется только как текст одного блока поста. Он не управляет кнопками, командами, БД, отправкой или другими частями сообщения; инструментов у модели нет.
- Ответ всегда проходит очистку и экранирование (п. 7). Худший исход injection — неудачный текст в 2–3 предложения без разметки, ссылок и пингов.

### 7. Ответ модели

Очистка выполняется в `render/` при сохранении, экранирование — при сборке поста:

- управляющие символы и переводы строк заменяются пробелами, повторные пробелы схлопываются;
- удаляются ссылки (`http://`, `https://`, `tg://`, `www.`, доменоподобные слова вроде `example.com`, `t.me/...`) и все символы `@`, поэтому Telegram не построит mention или ссылку;
- текст обрезается до первых трёх предложений;
- жёсткий предел — **400 символов** после очистки. Более длинный ответ считается слишком длинным и отбрасывается целиком (`failed`), а не режется посередине фразы;
- пустой после очистки ответ — `failed`;
- при сборке поста текст экранируется `html.escape` и выводится курсивом. Имена остаются текстом без mention-сущностей.

### 8. Сбои

- Общий таймаут запроса — 20 секунд на соединение, заголовки и тело вместе. Тело ответа ограничено 64 КБ.
- Таймаут, сетевая ошибка, HTTP-статус не 2xx, неверный JSON, отсутствие текста, пустой или слишком длинный ответ дают `failed`. Повторного запроса нет.
- В лог пишется только класс ошибки и HTTP-статус, без ключа, имён и текста ответа.
- Пост собирается из сохранённой хроники, если она `ready` к моменту подготовки поста. В остальных случаях пост выходит без хроники, как раньше. Публикация никогда не ждёт модель.

### 9. Понедельничный пост

Порядок блоков: итог задания прошлой недели, топ-3, **хроника**, новое задание. Текст поста, как и раньше, фиксируется в `daily_fortunes.rendered_text` при первой подготовке и повторяется по правилам `sent_at`, поэтому хроника выходит один раз вместе с постом.

### 10. Справка

Если ключ задан, в разделе «Приватность» справки появляется строка о том, что раз в неделю имена игроков и игровая статистика прошлой недели передаются внешнему сервису OpenCode Go для хроники, а текст сообщений не передаётся.

### Не входит

Чтение и пересказ сообщений, хроника за произвольный период или по запросу, хроника в статистике, команда включения в чате, LLM в других механиках, ручная модерация хроник.

## Последствия

### Положительные

- Недельный цикл получает живой итог без новых сообщений и без изменения бюджета шума.
- Один короткий запрос на активный чат в неделю: стоимость пренебрежимо мала.
- Сбой провайдера никогда не ломает и не задерживает пост; без ключа бот работает как раньше.
- Новый пакет не устанавливается.

### Отрицательные и ограничения

- Отображаемые имена и игровая статистика уходят стороннему сервису. Это меняет обещание приватности и требует строки в справке. OpenCode маршрутизирует запросы к провайдеру модели; политика хранения зависит от выбранной модели и может меняться. Смена модели — повод перепроверить таблицу приватности OpenCode.
- Модель может ошибиться в фактах или написать неудачную шутку; ручной модерации нет. Очистка ограничивает только форму, а не смысл.
- Формат аутентификации по документации явно не подтверждён; проверит ручной смоук.
- Перезапуск во время запроса теряет хронику этой недели.
- Откат: удалить ключ из окружения. Таблица `chronicles` остаётся и не мешает старому коду.

## Рассмотренные альтернативы

- **Официальный SDK OpenAI.** Отклонён: новая зависимость ради одного POST-запроса; `aiohttp` уже есть.
- **`urllib` в потоке, как в клиенте подарков.** Отклонён: aiohttp даёт настоящий асинхронный общий таймаут без потоков.
- **Генерация в момент публикации.** Отклонена требованием Product Owner: задержка модели сдвигала бы пост.
- **Генерация в проходе ежедневного поста с таймаутом.** Отклонена: последовательный проход по чатам ждал бы модель и задерживал посты других чатов.
- **Повтор запроса после сбоя.** Отклонён: требование — один запрос на чат в неделю; хроника необязательна.
- **Обрезка длинного ответа посередине.** Отклонена: обрывок фразы хуже отсутствия хроники; предложения сверх трёх отбрасываются целиком, а ответ длиннее предела — весь.
- **DeepSeek V4.1 Flash (`deepseek-v4.1-flash`) по умолчанию.** Рассмотрена по предложению Product Owner и отклонена 2026-11-08. Модель тоже отвечает через Chat Completions и не обучается на запросах, но нулевое хранение действует по договору, который продлевается помесячно (на дату решения — до 30.11.2026), а для её работы в воркспейсе OpenCode нужно включить регион Global: по умолчанию Go разрешает только Европу и США. Её можно включить вручную через `PIGEON_CHRONICLE_MODEL=deepseek-v4.1-flash` после включения региона Global.
- **Anthropic Messages или Responses API.** Отклонены для модели по умолчанию: выбранная модель отвечает через Chat Completions, это самый распространённый и простой формат.
- **Генерация в любой день, когда пост ещё не вышел.** Отклонена: понедельничный пост не восстанавливается после понедельника, запрос был бы потрачен впустую.
