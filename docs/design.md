# Дерзкая голубятня — дизайн

Статус: v0.4. Разделы 1–16 описывают существующее поведение; раздел 16 содержит реализованные правила разнообразия R1–R3 и имеет приоритет над более ранним описанием этих механик. Изменения решений фиксируем здесь с пометкой «изменено: дата, причина». Полное описание закрытых механик осталось в git-теге `pre-dovecote` (файл `DESIGN.md` в корне), нереализованные идеи ведутся в [GitHub Issues](https://github.com/madduck-tech/pigeon-bot/issues?q=is%3Aissue%20state%3Aopen%20label%3Aenhancement), а историческая справка о закрытых механиках — в [ideas.md](ideas.md). Запуск и обновление описаны в [operations.md](operations.md).

---

## 1. Суть

Telegram-бот-шутка для чатов сообщества madduck: **Дерзкая голубятня**, [@golubinskity_bot](https://t.me/golubinskity_bot). В текстах бота и здесь для краткости просто Голубятня. Она время от времени выпускает в групповой чат голубя со случайным именем, а участники в него плюют или прогоняют его.

- Бот работает в одном или нескольких групповых чатах. Состояние каждого чата полностью независимо.
- Личных сообщений нет.
- Типичный чат: ~6 участников, низкая активность.

**Цели:** оживить тихий чат и не быть назойливым.

**Не цели:** модерация, распознавание изображений, LLM в ядре механик, глобальный рейтинг между чатами, личные сообщения.

### Персонаж

- Аватар и образ: `assets/avatar.png`. Компания голубей во дворе: кепки, шапки, спортивные костюмы, золотые цепи, семечки, вид дерзкий. Образ уличный, с подписями и юмором в том же духе.
- Тон и юмор — дворовый, но без реальных оскорблений участников. Шутки про голубя, ритуал и двор, а не про людей.
- Это игра про нарисованного персонажа. Ни в текстах, ни в описаниях не призываем обижать настоящих птиц и не смеёмся над теми, кто их любит.
- Для публичного аватара в Telegram используем этот же файл. На нём один из голубей с сигаретой: перед публикацией стоит убедиться, что это подходит для чата участников.
- Голубь не один: каждый прилёт — новый голубь с именем из `content/names.yaml`. Имена в текстах только в именительном падеже, чтобы их не приходилось склонять.

## 2. Ограничения Telegram

Проверять по актуальной документации Bot API при реализации: поведение API меняется.

- **Privacy mode.** Боту не нужно читать сообщения чата: ему хватает команд и нажатий на кнопки. Privacy mode можно оставить включённым. Бот-админ всё равно получает все сообщения, поэтому права админа ему не нужны для игры. Если в чате есть другие боты, команду надёжнее писать с именем бота: `/pigeon@имя_бота setup`.
- **Анонимные админы.** Их команды приходят от служебного аккаунта, а `sender_chat` равен самому чату. Такая команда считается командой админа.
- **Миграция в супергруппу.** Меняет `chat_id`. Обрабатываем update `migrate_to_chat_id` и переносим данные. Если новый `chat_id` уже настроен через `/pigeon setup`, чаты не сливаем: старый выключается, его данные остаются в базе.
- **callback_data** — не больше 64 байт.
- **Редактирование сообщений** ограничено по частоте. Ошибку «message is not modified» игнорируем.
- **Форматирование.** Все сообщения идут с `parse_mode=HTML`. Всё, что пришло извне (имена участников) или из контента, экранируется в `render/`. Markdown не используем: `_` и `*` в именах ломают отправку.

## 3. Мультичат

- Все таблицы содержат `chat_id`. Все запросы фильтруются по нему.
- Чат неактивен, пока админ не выполнит `/pigeon setup`.
- Участник идентифицируется парой `(chat_id, user_id)`. Статистика хранится по чатам. Глобального рейтинга между чатами нет.

## 4. Архитектура

**Стек:** Python 3.12, aiogram 3 (long polling), SQLite (`sqlite3` + тонкий слой репозиториев), pydantic-settings для конфига, pytest.

**Слои:**

| Слой | Ответственность |
|---|---|
| `handlers/` | Входящие апдейты: команды и callback_query. Тонкие, без логики. |
| `services/` | Бизнес-логика механик. Не зависит от aiogram, тестируется отдельно. |
| `repo/` | Доступ к SQLite. |
| `scheduler/` | Tick-цикл раз в 30 секунд: планирует прилёты, выпускает голубей, закрывает просроченные. Переживает рестарт, потому что состояние в БД. |
| `budget/` | Лимиты спонтанных сообщений, тихие часы, пауза. |
| `render/` | Тексты сообщений и HTML-разметка. |
| `telegram/` | Адаптер над aiogram: отправка, редактирование, клавиатуры. Сервисы не знают про aiogram. |
| `content/` | YAML с контентом (см. §12). |

**Время.** Передаётся через clock-объект. В тестах подменяется.

## 5. Модель данных

Все таблицы с `chat_id` изолированы по чатам.

```
chats(chat_id PK, enabled, timezone, quiet_start, quiet_end, paused_until, created_at)

members(chat_id, user_id, display_name, PK(chat_id, user_id))

events(id, chat_id, status, source, pigeon_name, intro, opened_at, closes_at, message_id)
  status: open | closed
  source: manual | auto
  pigeon_name и intro выбираются при прилёте и хранятся, потому что сообщение редактируется.

hits(event_id, chat_id, user_id, created_at, PK(event_id, user_id))

shoos(event_id, chat_id, user_id, action, reaction, flew, created_at, PK(event_id, user_id))
  flew = 1 у попытки, которая спугнула голубя.

trophy(chat_id PK, holder_user_id, holder_name, since)
trophy_log(id, chat_id, user_id, started_at, ended_at)

points_ledger(id, chat_id, user_id, delta, reason, ref_id, created_at)
  reason: hit

achievements(chat_id, user_id, code, awarded_at, PK(chat_id, user_id, code))

fortunes(chat_id, user_id, local_day, PK(chat_id, user_id, local_day))

daily_fortunes(chat_id, local_day, PK(chat_id, local_day))
  Предсказание дня уже вышло в этом чате.

arrival_plans(chat_id, local_date, planned_at, status, PK(chat_id, local_date))
  status: pending | fired | skipped
```

**Очки.** Баланс = `SUM(delta)` из `points_ledger` по `(chat_id, user_id)`. Отдельных таблиц со счётом нет.

**Обновление со старой базы.** Таблицы закрытых механик не удаляются, код их просто не читает. При первом старте версия схемы (`PRAGMA user_version`) поднимается до 1. `points_ledger`, трофеи, достижения и история прилётов сохраняются, а старые `username` стираются, потому что они больше не нужны. Изменено 2026-11-06: описание исправлено по реализации и ADR-0001; очистка рейтинга при обновлении не выполняется.

## 6. Ядро: прилёт голубя

1. Scheduler раз в день решает, прилетит ли голубь сегодня, и выбирает случайное время в окне. День выбирается с вероятностью `осталось прилётов / осталось дней недели`, поэтому 3 прилёта приходятся на случайные дни всей недели, а не на её начало.
2. **Бюджет.** Если спонтанный лимит (§9) исчерпан, в этот день прилёта нет. Сорвавшийся прилёт не теряется: остаток переходит на оставшиеся дни недели.
3. Голубятня выбирает случайное имя (`content/names.yaml`) и случайную фразу (`content/arrivals.yaml`) и отправляет:

   ```
   🕊 Голубь Гена прилетел на подоконник. Курлык!

   💦 Попаданий: 0
   ```

   Под сообщением кнопки: `💦 Плюнуть` · `📣 Прогнать`.

   Создаётся `events` со `status=open` и `closes_at = now + 15 мин`. Если сообщение не отправилось и на него никто не нажал, событие удаляется: прилёта не было, и он не тратит бюджет. Если нажатия есть, сообщение дошло, а потерялся только ответ Telegram, и событие остаётся.
4. **Плевок** — §7.1. **Прогон** — §7.2. **Трофей** — §7.3.
5. Голубь улетает, когда его спугнули или когда наступил `closes_at`. Сообщение редактируется, кнопки исчезают:

   ```
   🕊 Голубь Гена улетел.

   📣 Маша: БУРУБУРУБРУ! Голубь сорвался с карниза
   💦 Попаданий: 3
   📣 Кто спугнул: Маша
   ```

   Если никто не спугнул, вместо двух строк про это пишется `💤 Улетел сам, никто не спугнул.`

## 7. Механики

### 7.1 Плевок (`hit`)

- Нажатие `💦 Плюнуть` на открытом прилёте.
- Один плевок на пользователя на прилёт.
- +1 очко в ledger.
- Счётчик в сообщении обновляется, новых сообщений нет. Нажавший видит всплывающий ответ «💦 Попал!».

### 7.2 Прогон (`shoo`)

- Нажатие `📣 Прогнать` на открытом прилёте. Одна попытка на пользователя на прилёт. Очков не даёт.
- Шанс спугнуть зависит от числа попыток на этом голубе: 20%, 35%, 50% и так далее, +15% за каждую, до 100%. Так один человек редко завершит раунд первым нажатием, а настоящий прогон получается общим делом.
- Действие и реакция голубя случайны (`content/shoos.yaml`) и дописываются в сообщение о прилёте. Показываем 3 последние строки. Новых сообщений нет.
- Формулировки без рода: «Вася: топ ногой!», а не «Вася топнул». Пол по имени не угадываем.
- Если голубь спугнут, прилёт закрывается сразу (§6, пункт 5).

### 7.3 Золотой плевок (трофей)

- Трофей переходит к участнику, который **первым** попал в прилёте.
- Владелец держит трофей до следующего перехода. Дни владения копятся через `trophy_log`.
- Виден в `/pigeon stats` и `/pigeon profile`.

### 7.4 Достижения (`achievements`)

Выдаются один раз на `(chat_id, user_id, code)`.

| Код | Условие | Название |
|---|---|---|
| `sniper` | Попадание в 5 прилётов подряд | Снайпер |
| `early_bird` | Первый плевок в 5 прилётах | Ранняя пташка |
| `trophy_holder` | Суммарно ≥ 7 дней держал Золотой плевок | Держатель трофея |
| `scarer` | Спугнул 5 голубей | Гроза голубей |

Тексты — в `content/achievements.yaml`, условия — в `services/achievements.py`.

Отдельных сообщений об ачивках нет: они показываются во всплывающем ответе на нажатие и в `/pigeon profile`. `trophy_holder` выдаётся молча раз в сутки, когда Scheduler планирует день: время идёт и без событий.

### 7.5 Предсказание (`fortune`)

- **Предсказание дня.** Голубятня сама публикует одно общее предсказание раз в сутки на чат, через час после конца тихих часов: по умолчанию в 10:00 по timezone чата. Если свободных часов так мало, что этот час попадает в тихие, выходит в последний свободный час.
- Если бот был выключен или чат настроили позже, предсказание выйдет при первой возможности в этот же день. В тихие часы оно не выходит, а день на паузе не тратится: после снятия паузы предсказание выйдет.
- Если отправка не удалась, она повторяется. Если потерялся только ответ Telegram, в чате будет лишний пост: это редко и дешевле, чем потерять день.
- `/pigeon fortune` — личное предсказание, один раз в сутки на участника. Ответ только запросившему, через reply на его команду. С предсказанием дня не связан.
- Тексты общие, из `content/fortunes.yaml`. Очков не даёт.

### 7.6 Этап 2: голубиный факт и погода (не реализовано)

Голубь сам приносит весть, поэтому отдельных спонтанных сообщений нет и бюджет не меняется.

- При прилёте в сообщение добавляется случайный факт о голубях (`content/facts.yaml`) или текущая погода.
- `/pigeon fact` — случайный факт по запросу.
- `/pigeon weather` — погода в городе чата.
- Погода берётся из API без ключа, например Open-Meteo. Город задаёт админ через `/pigeon setup`. Если города нет, бот показывает только факты. Если API недоступен, прилёт всё равно происходит.

## 8. Бюджет и анти-шум

**Спонтанное сообщение** здесь одно: прилёт. **Плановое** тоже одно: предсказание дня, раз в сутки на чат. Оно не входит в лимит прилётов, иначе съело бы его весь. Остальное бот пишет по запросу или редактирует уже отправленное.

**Лимиты (на чат):** спонтанных не больше 1 в сутки и 3 в неделю. Дни прилёта случайны в пределах недели (§6).

**Пользовательские действия** — кнопки и `/pigeon ...`. По чату не лимитируются. По участнику: один плевок и одна попытка прогона на прилёт, одно предсказание в сутки.

**Тихие часы** — по умолчанию 23:00–09:00 по timezone чата. Бот ничего не публикует сам. Кнопки и команды работают.

**Пауза.** `/pigeon pause 24h | 7d | off` — админ. Во время паузы бот ничего не публикует сам.

**Ручной прилёт.** `/pigeon arrive` — действие админа: работает в тихие часы и в паузу и не тратит лимит.

**Без пингов.** Имена в сообщениях — текст. Бот не использует mention-сущности.

## 9. Команды

| Команда | Кто | Что делает |
|---|---|---|
| `/pigeon` | все | Статус: кто сидит на подоконнике |
| `/pigeon help` | все | Что бот умеет и что хранит |
| `/pigeon stats` | все | Держатель Золотого плевка и рейтинг, топ-10 |
| `/pigeon profile` | все | Очки, ачивки, дни с трофеем |
| `/pigeon fortune` | все | Предсказание, раз в сутки |
| `/pigeon setup` | админ чата | Показать кнопки выбора часового пояса. Голубятня открывается после выбора. Повторный вызов меняет пояс |
| `/pigeon setup <пояс>` | админ чата | То же сразу, например `Europe/Moscow` |
| `/pigeon quiet <с> <до>` | админ чата | Тихие часы, например `23 9` |
| `/pigeon pause 24h\|7d\|off` | админ чата | Пауза автопубликаций |
| `/pigeon arrive` | админ чата | Выпустить голубя вручную |

## 10. Callback data

Формат: `pg:<action>:<id>`. Всегда ≤ 64 байт.

| Action | Пример | Что делает | Кто может |
|---|---|---|---|
| `hit` | `pg:hit:123` | Плевок | все |
| `shoo` | `pg:shoo:123` | Прогон | все |
| `tz` | `pg:tz:Europe/Moscow` | Выбор часового пояса | только админ чата |

В `tz` вместо id стоит имя пояса: так кнопка не зависит от порядка списка. Принимаются только пояса из `content/timezones.yaml`. Обработчик прилётов проверяет, что прилёт принадлежит этому чату и открыт, а пользователь ещё не действовал. Кнопки старых механик получают ответ, что они больше не работают.

## 11. Рендер

- Заголовки и имена — `<b>`, реакции голубя и предсказания — `<i>`.
- Тексты лежат в `render/texts.py` и `content/`, `render/` собирает из них разметку и экранирует вставки.
- Всплывающие ответы на кнопки разметку не поддерживают и остаются простым текстом.

## 12. Конфиг и контент

**Переменные окружения:**
- `PIGEON_BOT_TOKEN` — токен бота;
- `PIGEON_DB_PATH` — путь к SQLite, по умолчанию `./data/pigeon.db`;
- `PIGEON_CONTENT_DIR` — папка с YAML-контентом, по умолчанию `./content`;
- `PIGEON_LOG_LEVEL`.

**Настройки механик** лежат константами рядом с механиками.

**Контент** — `content/*.yaml`, меняется без правки кода и проверяется при старте:
- `names.yaml` — имена голубей;
- `arrivals.yaml` — фразы прилёта с `{name}`;
- `shoos.yaml` — действия при прогоне и реакции голубя;
- `fortunes.yaml` — предсказания;
- `achievements.yaml` — названия ачивок;
- `timezones.yaml` — варианты часового пояса в `/pigeon setup`.

## 13. Тестирование

- **Сервисы** — юнит-тесты без Telegram: ledger, ачивки, бюджет, шанс прогона.
- **Репозитории** — тесты на временной SQLite, включая обновление старых баз.
- **Telegram** — настоящая маршрутизация aiogram с фейковой сессией.
- **Время** — через clock, никаких реальных задержек.
- **Ручной смоук** — тестовый чат с двумя аккаунтами: прилёт, плевок, прогон, форматирование, статистика.

## 14. Этапы

**Этап 1 — Голубятня.** Случайные голуби и фразы, прогон, Золотой плевок, новые ачивки, HTML-разметка, удаление закрытых механик.

**После этапа 1.** Предсказание дня (§7.5).

**Этап 2 — вести от голубя.** Факты и погода (§7.6).

## 15. Журнал решений

- Ретроспективная регистрация (2026-11-06): текущие продуктовые, архитектурные и эксплуатационные решения оформлены в [ADR-0002–0011](adr/README.md). Документы фиксируют существующее поведение и не меняют правила.

- Разнообразие (2026-11-05, реализовано): R1–R3 — колоды предсказаний, переменные плевки и типы голубей, недельный цикл без дополнительных автоматических сообщений. Основание: [ADR-0001](adr/0001-diversify-pigeon-experience.md); правила и миграции закреплены в §16.

- v0.1 — первый черновик. Подробные решения M1–M3 и описания механик остались в `DESIGN.md` на теге `pre-dovecote`.
- Завершение разработки (изменено 2026-11-02): M4 отменён, потому что фич уже достаточно.
- Голубятня (изменено 2026-11-02): проект упрощён по решению владельца, потому что игра расползлась, а нравятся в ней прилёт и плевок.
  - Бот теперь Голубятня, а голуби разные: случайное имя и фраза на каждый прилёт. Голосование за имя отпало.
  - Новая кнопка `Прогнать`. Шанс растёт с числом попыток, а попытка одна на участника: иначе один человек завершал бы раунд сам.

## 16. Реализованное разнообразие R1–R3

Этот раздел описывает реализованные правила R1, R2 и R3 поверх базового поведения в §1–15. Для этих механик он имеет приоритет при расхождении с более ранним описанием. Подробности и границы решения: [спецификация](variety-spec.md), [план реализации](variety-plan.md) и [ADR-0001](adr/0001-diversify-pigeon-experience.md). Номера подразделов и ссылки внутри приведённой спецификации относятся к ней.

### Общие ограничения R1–R3

- Состояние каждого чата изолировано, все новые записи и запросы содержат `chat_id`; SQLite сохраняет состояние между перезапусками. Случайность передаётся через `random.Random`, время — через clock.
- Баланс меняется только через `points_ledger`, старые очки сохраняются. Новые кнопки и чтение сообщений чата не требуются; имена не пингуются, контент и имена экранируются в `render/`.
- Сохраняются лимит автоматических прилётов (1 в сутки и 3 в неделю), тихие часы и пауза. Действия и выполнение задания редактируют существующее сообщение прилёта; понедельничный итог заменяет ежедневный пост. Новых автоматических сообщений нет. Ручной прилёт сохраняет существующие исключения из лимита, тихих часов и паузы.

### 3. R1: предсказания

#### 3.1. Формат контента

`content/fortunes.yaml` становится списком объектов:

```yaml
- id: seeds-fall
  format: classic
  text: Сегодня семечки упадут в твою сторону.

- id: gena-saw-bread
  format: scene
  text: "{name} видел булочку на подоконнике. Решил не спрашивать, чья она."

- id: feather-prophecy-1
  format: serial
  part: 1
  next: feather-prophecy-2
  text: Первое перо упало. Голубь сказал, что второе расскажет всё завтра.
```

Правила:

- `id` обязателен, уникален и состоит из строчных латинских букв, цифр и дефисов.
- После публикации идентификаторы не переиспользуются для другого текста.
- `format` — один из `classic`, `omen`, `scene`, `spread`, `chat`, `serial`.
- `text` непустой; многострочный текст разрешён через YAML block scalar.
- Только `scene` может содержать `{name}`. Имя выбирается из `content/names.yaml` при подготовке выдачи.
- `serial` имеет `part`, начиная с 1, и может иметь `next`. Цепочка содержит 2–3 части, не имеет циклов и доступна только общему предсказанию дня.
- Загрузчик отклоняет неизвестные форматы, дубли ID, неверные ссылки `next`, циклы и неподходящие плейсхолдеры при старте.

Начальный набор — **60 записей**:

| Формат | Количество | Назначение |
|---|---:|---|
| `classic` | 30 | Текущие афоризмы с присвоенными ID |
| `omen` | 8 | Конструкция «если…, то…» |
| `scene` | 6 | Короткая сценка с участием случайного голубя |
| `spread` | 6 | Многострочный расклад «Удача / Опасность / Совет» |
| `chat` | 6 | Общее предсказание для участников чата |
| `serial` | 4 | Две цепочки по две части |

#### 3.2. Колоды

Константы:

- `FORTUNE_CHAT_EXCLUSION_DAYS = 14`;
- владелец общей колоды в БД — `owner_id = 0`;
- личная колода использует `owner_id = user_id`.

Общая и личные колоды независимы:

- общая содержит все форматы и выдаёт каждый доступный ID один раз за цикл;
- личная содержит все форматы, кроме `serial`;
- внутри новой колоды ID перемешиваются;
- первый ID новой колоды не совпадает с последним ID предыдущей, если доступно больше одного элемента;
- удалённые из контента ID пропускаются, новые ID добавляются в оставшуюся часть колоды в случайных позициях при следующей выдаче.

Личная колода дополнительно не выбирает ID, показанные этому чату в общих или личных предсказаниях за последние 14 локальных дней. Просмотр колоды не удаляет пропущенные из-за этого элемента. Если все оставшиеся элементы заблокированы, личная колода начинает новый цикл досрочно и выбирает из полного набора с тем же ограничением. Поэтому исключение недавних повторов в пределах чата приоритетнее длины личного цикла.

#### 3.3. Многочастные пророчества

- Первая часть попадает в общую колоду как обычный элемент.
- При её выдаче остальные части удаляются из остатка колоды и помещаются в персистентную очередь `forced_json` в порядке следования.
- В каждый следующий день общая колода сначала выдаёт очередную часть из `forced_json`.
- Принудительная часть не тратит дополнительный день и не создаёт дополнительный пост.
- Личные предсказания не запускают и не продолжают цепочки.
- При обновлении контента цепочка должна оставаться целой; иначе бот не запускается.

#### 3.4. Общее предсказание и повторная отправка

Время публикации определяет существующий `fortune.daily_due()`.

1. В транзакции бот проверяет строку `(chat_id, local_day)` в `daily_fortunes`.
2. Если строки нет, бот выбирает ID, сохраняет `fortune_id`, окончательный `rendered_text`, состояние колоды и `sent_at = NULL`.
3. Если строка с `sent_at = NULL` уже есть, бот использует её сохранённый текст, не продвигая колоду.
4. После успешного ответа Telegram бот записывает `sent_at`.
5. При ошибке отправки строка остаётся неотправленной, и следующий tick повторяет тот же текст.
6. Если ответ Telegram потерян после фактической доставки, возможен дубль того же поста. Это сохраняет текущий компромисс в пользу повторной попытки.
7. Строка с заполненным `sent_at` больше не отправляется.

Метод `release_daily_fortune()` после этого не используется для новой механики.

#### 3.5. Личное предсказание

- `/pigeon fortune` сохраняет лимит один раз на участника в локальные сутки.
- Выбор ID, обновление личной колоды и запись `(chat_id, user_id, local_day)` выполняются одной транзакцией.
- Повторная команда в тот же день по-прежнему возвращает `FORTUNE_ALREADY`, а не новый текст.
- Сохраняются `fortune_id` и `rendered_text`, чтобы история не менялась после редактирования YAML.

#### 3.6. Отображение

| Формат | Заголовок общего поста |
|---|---|
| `classic` | `🔮 Предсказание дня` |
| `omen` | `🌤 Голубиная примета` |
| `scene` | `🕊 Весть с подоконника` |
| `spread` | `🔮 Расклад от голубя` |
| `chat` | `🏘 Прогноз для района` |
| `serial` | `📜 Пророчество, часть N` |

Личный ответ использует тот же заголовок, но остаётся reply на команду участника. Текст помещается под заголовком; HTML-разметка внутри YAML не поддерживается, переносы строк сохраняются.

### 4. R2: переменный плевок

#### 4.1. Исходы обычного голубя

| `outcome` | Диапазон одного `rng.random()` | Шанс | Очки | Успешное попадание |
|---|---|---:|---:|---|
| `normal` | `[0.00; 0.65)` | 65% | +1 | да |
| `miss` | `[0.65; 0.85)` | 20% | 0 | нет |
| `cap` | `[0.85; 0.95)` | 10% | +2 | да |
| `chain` | `[0.95; 1.00)` | 5% | +3 | да |

Математическое ожидание: `0.65×1 + 0.20×0 + 0.10×2 + 0.05×3 = 1` очко за попытку.

После определения исхода реакция выбирается отдельным `rng.choice()` из `content/hits.yaml`. Для каждого исхода должно быть не менее шести реакций; для `cap_knocked` из §5 — не менее четырёх.

#### 4.2. Обработка попытки

- Лимит остаётся один `hit` на `(event_id, user_id)`, включая промах.
- Исход, реакция и начисленные очки сохраняются атомарно с попыткой.
- Для положительного результата создаётся запись `points_ledger(reason='hit')`; для нулевого запись не создаётся.
- `Попаданий` — это число успешных исходов `normal`, `cap`, `chain`, а не число попыток и не сумма очков.
- Первый успешный исход передаёт Золотой плевок. `miss` и `cap_knocked` трофей не передают.
- Повторное нажатие после любой попытки возвращает существующий `HIT_ALREADY`.
- Старые записи `hits` считаются `normal` с одним очком.

#### 4.3. Публичная история

- В сообщении прилёта показываются последние три действия из объединённой хронологии `hits` и `shoos`.
- Плевок отображается с именем участника, реакцией и очками, например: `💦 Вася: попал в кепку! +2`.
- Промах отображается как `💨 Вася: мимо. Голубь даже не моргнул`.
- Прогон сохраняет текущий формат.
- Под историей остаётся `💦 Попаданий: N`.
- Callback содержит результат, очки и новые ачивки. Он остаётся простым текстом.
- После закрытия прилёта итог содержит число попаданий и спугнувшего, если он есть.

### 5. R2: типы голубей

#### 5.1. Правила типов

| `pigeon_type` | Окно | Плевок | Прогон |
|---|---|---|---|
| `normal` | 15 минут | Базовые исходы | Базовые шансы |
| `capped` | 15 минут | Первая попытка в прилёте принудительно имеет исход `cap_knocked`, 0 очков; затем базовые исходы | Базовые шансы |
| `sleepy` | 15 минут | Базовые исходы | +15 процентных пунктов к шансу каждой попытки |
| `golden` | 5 минут | Базовые исходы, очки успешных попаданий ×2 | Базовые шансы |

Дополнительно:

- `cap_knocked` означает сбитую кепку, не засчитывается как попадание и не прерывает общий прилёт.
- Состояние кепки общее на прилёт и хранится в `events.type_state`.
- Для `sleepy` шансы по числу предыдущих попыток: 35%, 50%, 65%, 80%, 95%, 100%; далее 100%.
- Для `golden` множитель применяется к `normal`, `cap` и `chain`: +2, +4, +6. Промах остаётся нулевым.
- Ручной `/pigeon arrive` использует те же типы и правила.
- Старые и открытые во время миграции события получают `normal`.

Тип выводится отдельной строкой сразу после intro, например:

- `🧢 В кепке. Первый плевок только собьёт её.`;
- `💤 Сонный. Прогнать его проще.`;
- `✨ Золотой. Очки ×2, улетит через 5 минут.`.

#### 5.2. Колода типов

- На чат ведётся независимая перемешанная колода из 12 элементов: 9 × `normal` и по одному `capped`, `sleepy`, `golden`.
- Каждый новый прилёт, ручной или автоматический, берёт следующий элемент.
- Особый тип не может идти сразу после особого, в том числе на границе циклов. При перемешивании такая последовательность исправляется обменом с `normal`.
- Тип и состояние сохраняются в `events`; после открытия прилёта они не меняются.
- Удалённый или неотправленный прилёт возвращает взятый тип в ту же позицию колоды, чтобы сбой отправки не пропускал контент.

#### 5.3. Достижения и статистика

- `sniper` учитывает только успешные попадания в пяти последних прилётах; промах или сбитая кепка вместо попадания прерывают серию.
- `early_bird` учитывает только первые успешные попадания.
- `scarer` работает без изменений, включая `sleepy`.
- `trophy_holder` работает без изменений.
- Рейтинг использует фактический `points_ledger`, поэтому автоматически учитывает критические попадания и золотых голубей.

### 6. R3: недельный цикл

#### 6.1. Календарь

- Неделя начинается в понедельник 00:00 по timezone чата.
- `week_key` — ISO-дата понедельника.
- Задание создаётся лениво при первом scheduler pass новой недели.
- Очки недели вычисляются из `points_ledger` между локальными границами недели, преобразованными в UTC.
- Общий баланс и общий рейтинг не обнуляются.

#### 6.2. Задания

`content/quests.yaml` содержит стабильные `id`, название, описание, цель и название титула.

Начальная колода:

| `quest_id` | Условие выполнения | Титул |
|---|---|---|
| `trio-hit` | В одном прилёте успешно попали минимум 3 разных участника | Слаженный двор |
| `team-scare` | В одном прилёте попытались прогнать голубя минимум 3 разных участника | Шумный двор |
| `weekly-eight` | За неделю в чате совершено минимум 8 успешных попаданий | Меткий двор |
| `hit-then-scare` | Голубь спугнут после минимум 2 успешных попаданий в этом прилёте | Дворовая стратегия |

Правила:

- Одна колода заданий на чат содержит каждый `quest_id` по одному разу. Новый цикл не начинается с задания, завершавшего предыдущий.
- Прогресс вычисляется из `events`, `hits` и `shoos`, отдельные счётчики не дублируются.
- Выполнение проверяется после каждого плевка и прогона. В БД сохраняются `status=completed` и `completed_event_id`.
- Выполненное задание повторно не завершается. Невыполненное получает `status=failed` при закрытии недели.
- За выполнение не начисляются очки. Чат получает соответствующий постоянный косметический титул.
- Текущее задание и прогресс показываются в сообщении прилёта и `/pigeon stats`.
- Выполнение отмечается строкой в текущем сообщении прилёта без нового поста.

#### 6.3. Понедельничный пост

В понедельник существующий слот общего предсказания заменяется сообщением:

1. итог задания прошлой недели и полученный титул, если оно существовало;
2. топ-3 недели, если были очки;
3. новое задание недели.

Ограничения:

- Общая колода предсказаний в этот день не расходуется.
- Сообщение использует `daily_fortunes` и тот же механизм `sent_at`, что обычный ежедневный пост.
- Пауза и тихие часы действуют по текущим правилам. При запуске после понедельника прошедший понедельничный пост не восстанавливается.
- Если чат настроен не в понедельник, задание начинается в текущей неделе, а первый итог появится в следующий понедельник.

#### 6.4. Команды и титулы

- `/pigeon stats` по умолчанию показывает топ-10 текущей недели, текущее задание и последний полученный титул.
- `/pigeon stats all` показывает существующий общий топ-10 и держателя Золотого плевка.
- `/pigeon stats week` эквивалентен `/pigeon stats`.
- `/pigeon profile` дополнительно показывает очки текущей недели; общие очки и старые ачивки сохраняются.
- Титулы чата хранятся все, в интерфейсе выводится последний полученный.

### 7. Модель данных и миграции

Имена и точные SQL-миграции могут уточняться при реализации без изменения описанных правил.

#### 7.1. Изменения существующих таблиц

```text
fortunes
  + fortune_id TEXT NULL
  + rendered_text TEXT NULL

daily_fortunes
  + fortune_id TEXT NULL
  + rendered_text TEXT NULL
  + sent_at TEXT NULL

hits
  + outcome TEXT NOT NULL DEFAULT 'normal'
  + points INTEGER NOT NULL DEFAULT 1
  + reaction TEXT NOT NULL DEFAULT ''

events
  + pigeon_type TEXT NOT NULL DEFAULT 'normal'
  + type_state TEXT NOT NULL DEFAULT '{}'
```

Старые `daily_fortunes` получают ненулевой `sent_at`, потому что их отправка уже завершилась. Старые `fortunes` остаются с неизвестным `fortune_id`: восстановить прошлый текст невозможно.

#### 7.2. Новые таблицы

```text
fortune_decks(
  chat_id, scope, owner_id, cycle,
  remaining_json, forced_json, last_fortune_id,
  PK(chat_id, scope, owner_id)
)

pigeon_type_decks(
  chat_id, remaining_json, last_pigeon_type,
  PK(chat_id)
)

quests(
  chat_id, week_key, quest_id, status, completed_event_id,
  PK(chat_id, week_key)
)

quest_decks(
  chat_id, remaining_json, last_quest_id,
  PK(chat_id)
)

chat_titles(
  id, chat_id, quest_id, title, week_key, awarded_at
)
```

`scope` принимает `daily` или `personal`; для `daily` используется `owner_id=0`. JSON хранится как текст SQLite. Статус задания: `active`, `completed`, `failed`.

#### 7.3. Требования к миграции

- Миграции аддитивны, существующая база открывается без удаления данных.
- `points_ledger`, трофеи, достижения и старые события сохраняются.
- До первой новой выдачи невозможно исключить повтор последнего старого предсказания: старый текст не сохранялся. Гарантия начинается с записей, созданных после миграции.
- Открытые во время обновления прилёты остаются `normal` с исходным `closes_at`.
- Идемпотентность проверяется повторным запуском `Store` на одной базе.

### Проверки и критерии приёмки R1–R3

#### R1

- 60 валидных записей шести форматов загружаются при старте.
- Общая колода не повторяет ID до исчерпания; личные колоды разных участников независимы.
- Личная выдача исключает ID из 14-дневной истории чата.
- Обе цепочки выдаются по одной части в последовательные дни.
- Перезапуск не меняет остаток колоды и очередь частей.
- Ошибка отправки общего поста приводит к повтору того же текста без продвижения колоды.
- Чаты и локальные даты изолированы; пауза и тихие часы работают.

#### R2

- Границы вероятностей проверены детерминированными тестами; средняя базовая награда равна 1.
- Промах расходует попытку, не даёт очков, попадания, трофея или прогресса `sniper`.
- Первое успешное попадание передаёт трофей; критические очки попадают в ledger.
- Объединённая история показывает три последних действия и корректно экранирует имена.
- `capped`, `sleepy` и `golden` применяют точные правила §5.
- Колода типов не ставит два особых прилёта подряд и переживает перезапуск.
- Старая база сохраняет очки и корректно считает старые попадания.

#### R3

- Неделя и границы рейтинга соответствуют timezone чата, включая UTC-offset.
- Каждое задание завершается только при своём условии и только один раз.
- Понедельничный пост заменяет предсказание, не создаёт дополнительный пост и повторяется после ошибки отправки.
- `/pigeon stats`, `week`, `all` и `/pigeon profile` показывают согласованные очки.
- Титулы и состояние заданий переживают перезапуск и не смешиваются между чатами.
