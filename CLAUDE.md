# Дерзкая голубятня — инструкции для агента

## О проекте

Telegram-бот-шутка для чатов сообщества madduck. Бот — Дерзкая голубятня, @golubinskity_bot: она иногда выпускает в групповой чат голубя со случайным именем, а участники плюют в него или прогоняют его кнопками. Бот работает в одном или нескольких групповых чатах; состояние каждого чата независимо.

**Источник правды — `docs/design.md`.** Перед любым изменением поведения читай нужный раздел. Если реализация расходится с дизайном, сначала обнови `docs/design.md` (с пометкой, что изменилось и почему), а потом код.

**Локальные заметки.** Если в корне репозитория есть `CLAUDE.local.md`, прочитай его перед работой. Файл не попадает в git и дополняет эти инструкции.

**Универсальная конфигурация.** `AGENTS.md` направляет агентов любых harness в этот файл. Обязательный цикл задачи описан в `docs/development-flow.md`. Основная копия навыков находится в `.agents/skills/`, а `.claude/skills/` содержит идентичную копию для Claude; изменения синхронизируются между ними.

## Стек

- Python 3.12
- aiogram 3 (long polling)
- SQLite через `sqlite3` и тонкий слой репозиториев
- pydantic-settings для конфига
- aiohttp для запроса к LLM недельной хроники (ADR-0014)
- pytest

Стек зафиксирован в `docs/design.md` §4. Отклонения согласовывай с пользователем.

## Статус

Этап 1 (Голубятня) готов: случайные голуби и фразы, плевки, прогон, Золотой плевок, ачивки, рейтинг, профиль, предсказания (личное и ежедневное в чат), тихие часы, пауза, голубка с подарком 18+ по явному включению админом чата. Недельная хроника от LLM в понедельничном посте включается ключом OpenCode Go (ADR-0014). Этап 2 ещё не начат: голубиный факт и погода (`docs/design.md` §7.6). Закрытые механики лежат в git-теге `pre-dovecote`, идеи и баги — в GitHub Issues, запуск и обновление — в `docs/operations.md`.

Разнообразие предсказаний и прилётов описано в `docs/adr/0001-diversify-pigeon-experience.md`, `docs/variety-spec.md` и `docs/variety-plan.md`. Спецификация утверждена и реализована (R1–R3); `docs/design.md` описывает актуальное поведение.

## Архитектурные решения (ADR)

До изменения дизайна и кода создавай ADR для каждого значимого изменения:

- новой игровой механики или изменения правил существующей;
- новой команды, кнопки или автоматической рубрики;
- изменения архитектуры, модели данных или внешней интеграции;
- пересмотра ранее принятого архитектурного или продуктового решения.

ADR храним в `docs/adr/NNNN-short-title.md` с последовательной нумерацией и заносим в `docs/adr/README.md`. В документе фиксируем дату, статус, контекст, решение, последствия и рассмотренные альтернативы. Продуктовый ADR получает статус `accepted` только после согласования Product Owner; чисто технический — через ревью PR. Реализация начинается после принятия ADR.

ADR не заменяет `docs/design.md`: после принятия решения источник правды об актуальном поведении обновляется по-прежнему до кода. При пересмотре решения создаём новый ADR, связываем его с прежним и помечаем прежний как superseded, а не переписываем историю.

ADR не нужен для исправления ошибок без изменения задуманного поведения, рефакторинга, правки документации и добавления контента в рамках уже принятой механики.

## Команды

Установка (один раз):

```sh
python3 -m venv .venv
.venv/bin/pip install -e ".[dev]"
```

Проверки (Stage 1, от быстрой к медленной):

```sh
.venv/bin/ruff check .
.venv/bin/pytest
```

Тестовый стенд (Stage 2, нужен локальный `.env.stand`, см. `docs/operations.md`, «Тестовый стенд»):

```sh
.venv/bin/python -m tools.stand commands
```

Форматирование: `.venv/bin/ruff format .`. Новый код проходит и `ruff check`, и `pytest` до коммита.

Образ (Docker):

```sh
docker build -t pigeon-bot:local .
docker run --rm -e PIGEON_BOT_TOKEN=... pigeon-bot:local
```

CI (`.github/workflows/docker.yml`): тесты, затем сборка образа и push в `ghcr.io/madduck-tech/pigeon-bot`. Деплоя (CD) в репозитории нет — образ публикуется, а выкатывание делается вне этого репо.

## Правила работы с кодом

- **Изоляция чатов.** Каждый запрос к БД фильтрует по `chat_id`. Состояние чатов не хранится в глобальных переменных процесса.
- **Приватность.** Текст сообщений чатов не сохраняем, только метаданные: время, `user_id`, факт события. Это обещание есть в `/help`, его нельзя нарушать.
- **Без пингов.** В сообщениях бота имена пишутся текстом, без mention-сущностей. Бот не должен пинговать участников.
- **Шум.** Любое автоматическое сообщение проходит через `budget/` и тихие часы. Механика, которая постит сама, без этого не мержится.
- **Время.** В `services/` не вызывать `datetime.now()` напрямую. Используем инжектируемый clock, чтобы тесты были детерминированы.
- **Слоистость.** `services/` не импортирует aiogram. Telegram-специфика живёт в `telegram/` и `handlers/`.
- **callback_data.** Не длиннее 64 байт, формат из `docs/design.md` §10. Каждый обработчик кнопки проверяет, что нажимающий имеет право (например, что прилёт относится к этому чату).
- **Очки.** Любое изменение счёта только через `points_ledger`. Баланс не меняем напрямую.
- **Тексты.** Тексты бота на русском и лежат в `content/` или `render/`, а не захардкожены в логике. Идентификаторы и комментарии в коде на английском.
- **Разметка.** Сообщения идут с `parse_mode=HTML`. Всё, что вставляется из имён и контента, экранируется в `render/`.
- **Тесты.** Новая механика сопровождается тестами в `tests/services/`. Баги фиксируем с регрессионным тестом.

## Git

- Не коммитить и не пушить без явной просьбы пользователя.

## Структура репозитория

```
README.md         описание для людей
AGENTS.md         универсальная точка входа для агентов
CLAUDE.md         этот файл
.agents/skills/   основная копия навыков для разных harness
.claude/skills/   идентичная копия навыков для Claude
assets/           аватар и QR-код бота
content/          YAML-контент: имена, женские имена голубки, фразы прилёта, прогон, предсказания, ачивки, персонаж хроники
src/pigeon/       код бота
  handlers/       входящие апдейты (тонкий слой)
  services/       бизнес-логика механик, без aiogram
  repo/           доступ к SQLite
  scheduler/      tick-цикл прилётов
  budget/         лимиты спонтанных сообщений и тихие часы
  render/         тексты и HTML-разметка
  telegram/       адаптер над aiogram
  llm/            HTTP-клиент OpenCode Go для недельной хроники
tools/stand/      харнес тестового стенда в Telegram (вне прод-кода)
tests/            тесты
docs/
  design.md           дизайн и решения (источник правды о текущем поведении)
  development-flow.md цикл задачи, роли, проверки и релизы
  adr/                реестр, шаблон и документы решений
  variety-spec.md     спецификация разнообразия предсказаний и прилётов
  variety-plan.md     план её реализации
  operations.md       запуск, настройка, обновление и релизы
  ideas.md            историческая справка о закрытых механиках
```
