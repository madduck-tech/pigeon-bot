# Pigeon Bot — инструкции для агента

## О проекте

Telegram-бот-шутка для чатов сообщества madduck. Персонаж — голубь, который иногда прилетает в групповой чат, а участники его «плюют» кнопками, дартсом, дуэлями. Бот работает в одном или нескольких групповых чатах; состояние каждого чата независимо.

**Источник правды — `DESIGN.md`.** Перед любым изменением поведения читай нужный раздел. Если реализация расходится с дизайном, сначала обнови `DESIGN.md` (с пометкой, что изменилось и почему), а потом код.

## Стек

- Python 3.12
- aiogram 3 (long polling)
- SQLite через `sqlite3` и тонкий слой репозиториев
- pydantic-settings для конфига
- pytest

Стек зафиксирован в `DESIGN.md` §4. Отклонения согласовывай с пользователем.

## Статус

M1, M2 и M3 готовы: прилёты, плевки, трофей, дашборд, дартс, ставки, ачивки, квест, профиль, предсказания, пауза, дуэли, фото-голубь, голосование за имя. Разработка закончена: M4 отменён, новых механик не планируем. Сериал, почта, годовщина и погода описаны в `DESIGN.md`, но не реализованы.

## Команды

Установка (один раз):

```sh
python3 -m venv .venv
.venv/bin/pip install -e ".[dev]"
```

Проверки (Stage 1, от быстрой к медленной):

```sh
.venv/bin/ruff check .
.venv/bin/pytest
```

Форматирование: `.venv/bin/ruff format .`. Новый код проходит и `ruff check`, и `pytest` до коммита.

Образ (Docker):

```sh
docker build -t pigeon-bot:local .
docker run --rm -e PIGEON_BOT_TOKEN=... pigeon-bot:local
```

CI (`.github/workflows/docker.yml`): тесты, затем сборка образа и push в `ghcr.io/madduck-tech/pigeon-bot`. Деплоя (CD) в репозитории нет — образ публикуется, а выкатывание делается вне этого репо.

## Правила работы с кодом

- **Изоляция чатов.** Каждый запрос к БД фильтрует по `chat_id`. Состояние чатов не хранится в глобальных переменных процесса.
- **Приватность.** Текст сообщений чатов не сохраняем, только метаданные: время, `user_id`, факт события. Это обещание есть в `/pigeon help`, его нельзя нарушать.
- **Без пингов.** В сообщениях бота имена пишутся текстом, без mention-сущностей. Бот не должен пинговать участников.
- **Шум.** Любое автоматическое сообщение проходит через `budget/` и тихие часы. Механика, которая постит сама, без этого не мержится.
- **Время.** В `services/` не вызывать `datetime.now()` напрямую. Используем инжектируемый clock, чтобы тесты были детерминированы.
- **Слоистость.** `services/` не импортирует aiogram. Telegram-специфика живёт в `telegram/` и `handlers/`.
- **callback_data.** Не длиннее 64 байт, формат из `DESIGN.md` §11. Каждый обработчик кнопки проверяет, что нажимающий имеет право (например, только соперник принимает дуэль).
- **Очки.** Любое изменение счёта только через `points_ledger`. Баланс не меняем напрямую.
- **Тексты.** Тексты бота на русском и лежат в `content/` или `render/`, а не захардкожены в логике. Идентификаторы и комментарии в коде на английском.
- **Тесты.** Новая механика сопровождается тестами в `tests/services/`. Баги фиксируем с регрессионным тестом.

## Git

- Не коммитить и не пушить без явной просьбы пользователя.

## Структура репозитория

```
DESIGN.md        дизайн и решения (источник правды)
CLAUDE.md        этот файл
content/         YAML-контент: шутки, сериал, имена, предсказания, ачивки
src/pigeon/      код бота
  handlers/      входящие апдейты (тонкий слой)
  services/      бизнес-логика механик, без aiogram
  repo/          доступ к SQLite
  scheduler/     tick-цикл для задач по расписанию
  budget/        лимиты спонтанных сообщений и тихие часы
  render/        тексты и клавиатуры
  telegram/      адаптер над aiogram
tests/           тесты
docs/            вспомогательные материалы
```
